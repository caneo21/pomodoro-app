# 갤럭시 워치 6용 포모도로 앱 + 폰 연동 설계

- 작성일: 2026-08-13
- 상태: 승인됨 (구현 계획 수립 단계로 전환)

## 배경 / 목표

기존에 만든 안드로이드 폰용 포모도로 타이머 앱([2026-08-11-pomodoro-android-design.md](2026-08-11-pomodoro-android-design.md))과 함께 쓸 수 있는 갤럭시 워치 6(Wear OS)용 포모도로 앱을 만든다. 워치 앱은 폰 없이도 완전히 단독으로 동작하며, 폰과 블루투스로 연결되어 있을 때는 양쪽의 타이머 상태(재생/일시정지/리셋, 남은 시간, 집중/휴식 설정)가 서로 동기화된다.

## 기기 소유권 모델

- **워치는 폰의 원격 화면이 아니라 독립 실행형이다.** 워치 자체가 `TimerEngine`을 소유하고, 폰이 꺼져 있거나 블루투스 연결이 끊긴 상태에서도 워치만으로 포모도로 세션을 시작/진행/종료할 수 있다.
- 폰과 워치는 대칭 구조다. 어느 쪽에서 시작/일시정지/리셋을 하든 같은 코드 경로(로컬 엔진 갱신 → 동기화 계층에 기록)를 탄다.
- **설정(집중/휴식 시간)은 폰에서만 변경한다.** 워치는 그 값을 동기화로 받기만 하고, 워치에는 설정 화면을 넣지 않는다. (이유: 작은 워치 화면에서 슬라이더 조작이 불편하고, 양쪽에서 동시에 설정을 바꿀 때 생기는 충돌 처리가 불필요하게 늘어남.)

## 재연결 시 충돌 해결 정책

폰과 워치가 블루투스 연결이 끊긴 동안 각자 독립적으로 동작하다가 재연결되면, **가장 최근에 조작(시작/일시정지/리셋/설정 변경)된 쪽의 상태로 다른 쪽이 맞춰진다.** 각 동기화 페이로드에 조작 시각(`lastActionAtMillis`, 로컬 wall-clock 기준)을 담아 비교한다.

예: 폰에서 14:00에 일시정지, 워치는 연결이 끊긴 동안 계속 카운트다운하다 14:03에 리셋 → 재연결 시 14:03 리셋이 더 최근이므로 폰도 리셋 상태로 동기화된다.

이 정책은 두 기기의 시스템 시각이 서로 크게 어긋나지 않는다는 전제 위에 있다. 안드로이드/Wear OS 기기는 기본적으로 네트워크 시간(NTP)에 자동 동기화되므로 일반적인 사용 환경에서는 이 전제가 성립한다. 별도의 시계 보정 로직은 이번 범위에 넣지 않는다.

## 기술 스택 / 통신 방식

- 워치 앱: Kotlin + **Compose for Wear OS**, Wear OS Foreground Service
- 폰↔워치 통신: **Wearable Data Layer API** (Google Play Services, `com.google.android.gms:play-services-wearable`)
  - `DataClient` — 현재 타이머 상태(`SyncPayload`)를 저장. 연결이 끊겨 있어도 재연결 시 최신 값이 자동으로 상대방에게 전달되는 특성이 "최근 조작이 이김" 정책과 정확히 맞아떨어진다.
  - `MessageClient` — 즉각적인 명령(시작/일시정지/리셋) 전달용.
  - 실제 전송 경로(블루투스 클래식/BLE/Wi-Fi)는 시스템이 이미 맺어진 워치-폰 페어링(갤럭시 웨어러블 앱) 채널을 통해 자동으로 선택하며, 앱이 별도로 블루투스 소켓이나 권한을 직접 다루지 않는다.

**검토했지만 채택하지 않은 대안:**
- *원시 블루투스 소켓(Classic RFCOMM/BLE GATT) 직접 구현*: 워치-폰은 이미 Wear OS 페어링 채널로 연결되어 있어 별도 BT 연결은 그 채널과 충돌할 수 있고, 재연결·직렬화 프로토콜을 전부 손으로 구현해야 해서 Data Layer API 대비 이점이 없다.
- *클라우드(Firebase 등) 경유 동기화*: 계정/백엔드 인프라가 필요해지고 "블루투스로 연동"이라는 요구와 맞지 않아 제외.

## 모듈 구조

```
:core   (신규, 순수 Kotlin 모듈 — 안드로이드 의존성 없음)
  - TimerEngine, TimerState, TimerPhase   (기존 :app에서 이동, 로직 변경 없음)
  - SyncPayload(phase, isRunning, remainingMillis, totalMillis,
                focusMinutes, breakMinutes, lastActionAtMillis)

:app    (기존 폰 앱)
  - TimerService에 PhoneSyncClient 추가
      - 로컬에서 시작/일시정지/리셋/설정변경이 일어날 때마다 DataClient에 SyncPayload를 씀
      - 워치가 보낸 MessageClient 명령(시작/일시정지/리셋)을 받아 로컬 TimerEngine에 반영
      - 워치가 쓴 SyncPayload를 DataClient로 수신하면 lastActionAtMillis를 비교해
        더 최신이면 로컬 상태를 덮어씀

:wear   (신규 Wear OS 앱 모듈)
  - :core 의존
  - WearTimerService: 폰의 TimerService와 대칭 구조 (Wear OS Foreground Service,
    동일한 TimerEngine 기반 절대 종료 시각 계산 — 워치에서도 드리프트 없는 정확성 보장)
  - WearSyncClient: :app의 PhoneSyncClient와 대칭되는 반대편 구현
  - Compose for Wear OS 화면 1개
```

## 워치 화면 구성

설정 화면 없이 타이머 화면 1개만 존재한다.

- 중앙에 남은 시간(mm:ss) + 원형 프로그레스 링 (폰과 동일한 시각 언어)
- 현재 모드 텍스트: "집중" / "휴식"
- 하단 아이콘 버튼 2개: 시작/일시정지 토글, 리셋 (워치 화면 크기를 고려해 텍스트 버튼 대신 아이콘 사용)
- **Ambient mode 대응**: 화면이 어두워지는 저전력 모드에서는 흑백/저주사율로 남은 시간만 표시 (Wear OS 표준 패턴, 배터리 절약)
- 폰과의 연결 상태를 별도로 표시하지 않는다 (워치는 연결 여부와 무관하게 항상 정상 동작해야 하므로 상태 배지는 범위 제외)
- 최초 실행 시 워치에서도 `POST_NOTIFICATIONS` 권한을 요청한다

## 백그라운드 정확성 & 알림

- `WearTimerService`는 폰의 `TimerService`와 동일하게 Foreground Service + 절대 종료 시각 기반 계산을 사용한다 (`TimerEngine` 재사용으로 로직 자체는 검증된 것을 그대로 씀).
- **진행 중 표시**: 워치에는 폰의 "진행 중 알림" 대신 Wear OS 표준인 **Ongoing Activity API**(`androidx.wear.ongoing`)를 사용해 워치 화면 상단/워치 페이스에 "집중 중 · 12:34" 칩을 계속 노출한다.
- **세션 종료 시**: 진동(필수) + 사운드(선택, 워치 자체 방해금지 설정을 존중). 손목에 착용한 상태라 진동이 폰보다 핵심적인 신호다.
- 워치가 폰과 연결이 끊긴 채로 계속 동작해도 위 로직은 전부 로컬에서 독립적으로 이뤄진다. 동기화는 부가 기능이지 타이머 정확성의 필수 경로가 아니다.

## 테스트 계획

- `:core`의 `TimerEngine`은 기존 유닛 테스트를 그대로 이전한다 (로직 변경 없음).
- `PhoneSyncClient`/`WearSyncClient`의 "최근 조작이 이김" 판단 로직은 `DataClient`를 인터페이스로 감싸 순수 유닛 테스트로 검증한다 (실제 Play Services 없이).
- `WearTimerService`는 폰의 `TimerService`와 동일한 패턴이므로 계측 테스트(androidTest)를 작성한다. 폰 앱 구현 중 `ServiceTestRule`이 `onBind()`가 `null`을 반환하는 서비스에서는 연결 대기가 영원히 타임아웃되는 문제를 겪었으므로, 워치 서비스 테스트는 처음부터 `context.startService()`로 직접 기동하는 방식으로 작성한다.
- Wear Compose 화면은 Compose UI 테스트로 버튼 동작을 검증한다.
- **수동 검증**: 실제 갤럭시 워치 6와 폰을 갤럭시 웨어러블 앱으로 페어링한 상태에서 동기화 시나리오(양쪽에서 조작, 연결을 끊고 재연결)를 직접 확인한다. 에뮬레이터만으로는 실기기 간 블루투스 페어링 동작을 완전히 재현하기 어렵다.

## 범위 제외 (이번 범위 아님)

- 워치 페이스 컴플리케이션/타일 (향후 확장 후보)
- 워치를 여러 폰과 동기화하거나 계정 기반 클라우드 동기화
- 워치 전용 온보딩 화면 (기본값 25/5로 시작, 폰과 연결되면 곧 동기화됨)
- Apple Watch 등 Wear OS 이외 플랫폼
- 워치에서의 집중/휴식 시간 설정 변경 (폰 전용)
